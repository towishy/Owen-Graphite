Markdown Table Design Proposals v2

현재 결과물이 너무 평면적이거나 보고서 표처럼 느껴질 수 있어서, 기본 Markdown table 후보를 다시 잡았습니다. 이번 샘플은 “읽기 편한 기본값”과 “용도별 utility 후보”를 분리해서 비교합니다.

내 추천 기본값은 A 또는 B. 문서 감성은 A, PDF 안정성과 전문 보고서 느낌은 B가 더 좋습니다. C/D는 전체 기본값보다 class 옵션이 어울립니다.

A. Frosted Ledger

Owen Graphite의 glass+shadow 언어를 표에도 가장 자연스럽게 가져오는 후보. 너무 장식적이지 않게 grid를 얇게 유지합니다.

좋은 점테마 정체성이 가장 잘 살아납니다. 본문 표가 카드처럼 과하게 뜨지 않고, callout/codeblock과도 자연스럽습니다.
주의PDF에서는 blur가 평면화되므로 print 전용 색상 고정이 필요합니다.

B. Editorial Sheet

보고서와 PDF에 강한 후보. 헤더와 grid를 또렷하게 두고, 데이터 비교가 많은 문서에서 안정적으로 보입니다.

좋은 점가장 안정적입니다. PDF, 긴 문서, 업무 보고서에서 예측 가능한 결과가 나옵니다.
주의현재 느낌과 가장 가까워서 “새로움”은 A/C보다 약합니다.

C. Scan Zebra

행 단위 스캔을 빠르게 하는 후보. task/log/checklist류 표가 많은 문서에서 읽는 속도가 좋아집니다.

주의기본값으로 쓰면 일반 산문 문서에서는 표가 조금 바빠 보일 수 있습니다.

D. Dense Matrix

숫자와 상태 비교가 많은 표를 위한 촘촘한 후보. 기본 table보다 compact-table/numeric-table에 적합합니다.

좋은 점대시보드, 수치 비교, 리스크 매트릭스에 좋습니다. 한 페이지에 더 많은 행이 들어갑니다.
주의기본 Markdown table 전체에 적용하면 너무 조밀합니다.
적용 범위 제안: A 또는 B를 기본 Markdown table로 선택하고, C는 compact-table/task-table, D는 numeric-table/matrix-table 계열 utility에 적용하는 구성이 가장 안전합니다. Live Preview/PDF parity는 선택한 후보에 맞춰 별도 print fallback을 같이 설계해야 합니다.
